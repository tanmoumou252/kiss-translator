九、无障碍焦点环配对法则 (Focus Ring Pairing Law) 独立验收域

焦点环配对独立纳入审计（§6.2/§6.3 导航算法细节维持排除口径，不互含、不互豁免）。四条铁律：

① 无语义必无环：未接入键盘导航与 ARIA 语义（无 roving tabindex、无 menu/listbox/option/combobox 角色、无键盘事件接线）的组件，严禁渲染任何形态焦点环（:focus-visible 样式、.Mui-focusVisible 覆盖、outline/box-shadow 环均在内）。

② 有语义必有环：已接入无障碍语义的组件必须配对焦点环，环必须挂键盘语境伪类 :focus-visible（严禁挂输入方式无关的 .Mui-focusVisible 类——鼠标链路会误显环）；forced-colors 模式必须提供 outline 兜底形态（CanvasText 系统关键字，兜底块置于同选择器 :focus-visible 规则之后，顺序闸）。

③ 静默作用域一致：指针静默机制（focusModality 标记＋抑制 CSS）注入域必须与焦点环样式作用域一致——自建 ThemeProvider 的域若画环必须同步接入静默机制，任一单侧存在判配对断裂。

④ 夹具双向钉死：有语义处断言环形态（:focus-visible 键＋forced-colors 兜底），无语义处负向锁断言环样式键不存在。本项夹具与测试此前完全缺失（焦点环缺陷靠用户报告才发现、多轮才收敛），列为最高优先盲区，缺失即红。

⑤ 焦点指示单形原则（v3.3，v3.5 补 forced-colors 例外）：同一节点同一焦点态下 focus 染层与 outline 环不得双显——环型语义类（挂 .m3-semantic-focus：范例 A/B/C 菜单项、分段项、触发钮、胶囊成员）以 outline 环为唯一键盘焦点指示、focus 染层互斥禁用；染层型（Chip 等未挂该类节点）以 0.12 染层为唯一指示、严禁另画环（v3.5 唯一例外：forced-colors 下染层被固化为不透明系统色而失效，必须以 2px CanvasText outline 兜底，不构成单形违反）；无语义不可聚焦节点两者皆无、亦无 forced-colors 兜底。

⑥ 本页实现现状（v3.5）：环型语义类统一挂 .m3-semantic-focus，:focus-visible outline 环＋forced-colors（CanvasText）兜底块（置于环规则之后，顺序闸；v3.5 起同模板覆盖染层型节点）；focusModality 指针静默为逐元素 landed 校验标记（data-kt-focus-silent，scriptFocus 单一入口零裸 .focus()，见样式表 [v3.5 §6.4] 段与脚本 1.5 节）；模块五触发源入焦按 v3.5 优先级交付（选中 option → 未选中可用 option → menuitem 族，aria-disabled 排除、宁缺勿错）；菜单容器水平预留 4px padding 防 overflow 裁环。模块六 Chip 为染层型/无语义对照样本——不挂 .m3-semantic-focus、零环样式键。锁契约见规范附录 A。

十、下拉入口（触发框）本体度量衡与语义配对 (Trigger Entry Audit) 入口本体入锁

入口本体纳入审计与锁：真下拉（MUI Select / combobox）与伪下拉（自绘菜单触发钮）一律适用；下游菜单内部合规不得替代或豁免入口本体检查。

几何与字体逐项入锁：入口高度、padding、圆角、字号、字重、行高、文本溢出（ellipsis）逐项须有夹具与测试钉住，缺锁即红。

选型铁律同树约束：入口控件类型同样受排他性决策树约束（二元布尔误用下拉、2≤N≤5 短文案误用下拉等即红），不得因下游菜单合规而豁免。

语义配对登记：入口必须声明 aria-haspopup、aria-expanded 与 aria-controls（v3.3 声明义务），开合变更必须同步翻转 aria-expanded（翻转义务），并登记下游菜单语义类型（动作菜单 / 数据单选 / 数据多选）——入口与下游类型不匹配即红。本页范例 A/B 触发钮已按声明＋翻转义务接线（aria-haspopup / aria-expanded / aria-controls＋toggle 同步翻转＋Escape 回退）。

状态与回退：hover/active/focusVisible 保留 State Layer 瞬时反馈；焦点环遵守模块九配对法则；Escape 收起浮层后焦点必须回退至入口本体（opener 接线义务）。
