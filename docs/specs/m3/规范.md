## 一、总则与宿主环境强隔离 (Plugin Host Isolation)

Content Script 运行于复杂多变的第三方宿主页面（如 GitHub、知乎、各类 CMS 及内网系统）。**任何对宿主全局环境的假设与修改均属致命事故。**

### 1.1 Shadow DOM 宿主样式防御与 `all: initial` 挂载法则
- **强制 Shadow DOM 封装**：所有外显浮动气泡、悬浮球（FAB）及配置面板必须封装在 `attachShadow({ mode: 'open' })` 或 `attachShadow({ mode: 'closed' })` 中。
- **严禁直接在 `:host` 声明 `all: initial`**：
  - *缺陷规约*：在 `:host` 声明 `all: initial` 会重置宿主级盒模型属性并干扰外部通过 CSS 自定义属性传参。
  - *强制准则*：保持 `:host { display: inline-block; box-sizing: border-box; }`，**必须在 Shadow Root 内部的第一级包装容器（Wrapper Div）声明 `all: initial`**。

```css
/* 标准 Shadow DOM 样式骨架 */
:host {
  display: inline-block;
  box-sizing: border-box;
}

.m3-plugin-root {
  all: initial; /* 阻断宿主网页激进样式继承（如 * { box-sizing: content-box !important; }） */
  display: flex;
  flex-direction: column;
  box-sizing: border-box;
  font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif;
  color: var(--md-sys-color-on-surface);
}

.m3-plugin-root *,
.m3-plugin-root *::before,
.m3-plugin-root *::after {
  box-sizing: border-box;
  font-family: inherit;
}
```

### 1.2 独立主题沙箱 (Theme Scoping 禁令)
- **绝对严禁污染 `body`**：严禁向宿主执行 `document.body.classList.toggle('dark-mode')`。这会直接破坏宿主网页原生主题，或被宿主自带的暗黑样式覆盖。
- **主题挂载点**：亮暗主题仅允许挂载在 Web Component 自身的属性选择器 `:host([data-theme="dark"])` 或内部根容器 `.m3-plugin-root[data-theme="dark"]` 上。

### 1.3 现代系统级无依赖字体栈 (Font Fallback Engine)
- **严禁硬编码依赖 Google Fonts Roboto**：宿主网页通常未加载 Roboto，远程字体网络阻断会导致渲染回退至带衬线字体，字宽（Glyph Width）变化会导致单项截断或换行。
- **强制使用系统优先字体栈**：
  ```css
  font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif;
  ```

### 1.4 宿主事件强阻断 (Event Containment 铁律)
- **致命隐患**：Content Script 注入复杂宿主（GitHub、Gmail、Notion、Web IDE）时，宿主普遍监听 `window`/`document` 级快捷键。插件 UI 内的键盘事件即使调用了 `e.preventDefault()`，**仍会冒泡出 Shadow DOM 边界触发宿主逻辑**——方向键翻宿主页、`Escape` 关掉宿主全屏弹窗、`Space` 触发宿主可聚焦元素。
- **强制准则**：插件所有交互组件（Segmented Buttons、Menu、Listbox、TextField）的键盘监听，凡调用 `e.preventDefault()` 处**必须同步调用 `e.stopPropagation()`**；组件内鼠标点击（click）监听同理阻断冒泡。
- **事件收容清单（逐键核验）**：`ArrowUp/Down/Left/Right`、`Home`、`End`、`Escape`、`Space`、`Enter` ——六个导航键、一个回退键、两个确认键，全部不得经冒泡向宿主泄漏。
- **保证边界（口径限定）**：`stopPropagation` 只阻断事件在**自身监听节点之后**的传播段（冒泡及其后）；宿主挂载在 `window`/`document` 上的**捕获阶段**监听器在事件到达组件之前已经触发，组件监听器无法阻止其收到事件。本节逐键保证仅指阻断冒泡，不声称隔离宿主捕获监听器。若场景确需隔离宿主捕获监听器，交互 UI 必须置于**独立 iframe 浏览上下文**（独立事件传播路径），并另行验证焦点进出（iframe 聚焦交接）与事件隔离。

## 二、强调色角色体系与色彩哲学 (Accent Color Roles & HCT)

在 Material 3 中，**Primary、Secondary、Tertiary 是基于 HCT (Hue, Chroma, Tone) 算法构建的功能角色语法，绝非视觉权重递减的按钮样式**。

```
                    ┌─────────────────────────┐
                    │  Seed Color (基准种子色) │
                    └────────────┬────────────┘
                                 │
         ┌───────────────────────┼───────────────────────┐
         ▼                       ▼                       ▼
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│ Primary (主色)  │     │Secondary (次级色)│     │Tertiary (三级色)│
├─────────────────┤     ├─────────────────┤     ├─────────────────┤
│ • 保持原始色相   │     │ • 继承同款色相  │     │ • 色相顺时针旋转│
│ • 高对比/高彩度 │     │ • 彩度腰斩(Chroma≈16)│ 60° ~ 120°    │
│ • 全局唯一主行动│     │ • 莫兰迪灰调孪生│     │ • 跨色系温差对冲│
│ • 核心视觉锚点  │     │ • 高频平铺不刺眼│     │ • AI / 特色高光 │
└─────────────────┘     └─────────────────┘     └─────────────────┘
```

### 2.1 三大强调色角色矩阵

| 强调色角色 | HCT 算法生成机制 | 与 Primary 视觉关系 | 核心消费场景 (DO) | 严禁消费场景 (DON'T) | 搭配 Token (Container & Content) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Primary<br>(主强调色)** | 采用基准种子色（Seed Hue），维持高彩度与强对比。 | 基准本体 | • 页面唯一的全局核心行动点（Primary CTA）<br>• Switch 激活滑轨<br>• TextField 处于**当前聚焦（Focus）**态 | 严禁作为常规多项标签背景、普通次级操作。**单屏同视区原则上仅允许 1 处 Primary 实心按钮**。 | • 实心：`primary` + `on-primary`<br>• 浅底：`primary-container` + `on-primary-container` |
| **Secondary<br>(次级强调色)** | **同色相**，强制压低彩度（Chroma ≈ 16）。 | **同色系低彩度孪生兄弟** | • 分段控制器（Segmented Buttons）的选中背景<br>• 业务过滤标签（Filter Chips）的选中态<br>• 次要操作按钮（Filled Tonal） | 严禁用于最高优先级提交按钮；严禁用于承载危险警告或 AI 特性注记。 | • 选中底色：`secondary-container`<br>• 选中文字：`on-secondary-container` |
| **Tertiary<br>(三级点睛色)** | **色相旋转 60°~120°**，衍生出温差平衡色。 | **跨色系对照组（温差对冲）** | • **AI 深度释义**、智能翻译等差异化特性<br>• 实验性实验室功能角标<br>• 用暖色（琥珀/棕橙）平衡冷青界面 | 严禁作为通用表单提交按钮；严禁全屏大面积铺陈。 | • 标注底色：`tertiary-container`<br>• 标注文字/图标：`on-tertiary-container` |

### 2.2 `--kt-*` Token 结构登记（仓库映射）

本节把角色矩阵映射到仓库现行 token 结构，作为「颜色分级与明暗主题结构核查」的判定锚（**口径＝只查漏改与覆盖结构，不比对具体色值**）：

- **定义点（唯一）**：全部 `--kt-*` 角色 token 集中定义于 `src/styles/m3.js` 的 M3 token 表（如 `--kt-pri`＝primary、`--kt-secc`＝`secondary-container` 选中态容器色），与 `--md-sys-*` 语义角色一一对应；
- **消费义务**：组件样式一律以 `var(--kt-<role>)` 消费（现存消费点如 `src/views/Options/styles.js` 选中态容器色、`src/views/RuleEditor` 强调面），严禁组件内私造 hex（呼应 §1.2 主题沙箱与 §7 Token 统一）；
- **主题覆盖结构**：浅色与深色两套主题**均须**为每个 `--kt-*` 角色提供覆盖定义，任一角色在任一主题缺位即判漏改；
- **扩展纪律**：新增颜色角色必须先入本登记、再入组件；token 删除/改名必须同步本节与消费点盘点（夹具锁映射见附录 A）。

## 三、交互控件排他性选型决策树（铁律）

为杜绝“2 选 1 做下拉”、“单选列表误用菜单”等交互反模式，所有控制项必须依照 **“语义性质”**、**“选项容量 ($N$)”**、**“文案长度”** 执行排他性选型：

```
                             [ 这个配置项需要控制什么？ ]
                                         │
        ┌────────────────────────────────┼────────────────────────────────┐
   【二元状态】                     【具名实体互斥】                   【数据值选取】
(启用/禁用、开/关)              (几个界面行为中切换一个)           (长名单/节点/模型选取)
        │                                │                                │
        ▼                                ▼                                ▼
  ┌───────────┐                [ 一共有几个选项？(N) ]              ┌───────────────┐
  │  Switch   │                          │                         │    Listbox    │
  │ (物理开关) │                ┌────────┴────────┐                │  (数据列表框)  │
  └───────────┘             【2 ≤ N ≤ 5】       【N > 5】          └───────────────┘
                                │                 │
                        【文案是否简短？】        ▼
                         (≤4字/单行平铺)   ┌───────────────┐
                                │          │ Dropdown Menu │
                       ┌────────┴────────┐ │ (动作折叠菜单)│
                       │ 是              │ │ (空间极受限)  │
                       ▼                 │ └───────────────┘
              ┌─────────────────┐        │ 否
              │Segmented Buttons│        ▼
              │  (分段切换钮)   │ ┌───────────────┐
              └─────────────────┘ │  Radio Group  │
                                  │ (纵向单选组)  │
                                  └───────────────┘
```

### 3.1 详细判例与边界归约

#### A. 开关 (Switch)
- **硬性判据**：$N = 2$，语义为**独立二元布尔状态（Boolean：开 / 关）**，操作**即时生效**（无须点击保存）。
- **正面判据 (DO)**：剪贴板自动监听、划词即时弹出气泡、打字机流式渲染开关。
- **反模式禁令 (DON'T)**：严禁在两个具名实体之间使用 Switch（如“浅色 / 深色”、“对照 / 替换”）。开关只能表达单项特性的有无。

#### B. 分段控制器 (Segmented Buttons)
- **硬性判据**：$2 \le N \le 5$，属于**具名实体互斥选择**，选项文案简短（$\le 4$ 字），同屏展示无折行。
- **正面判据 (DO)**：译文呈现模式（`[双语对照]` `[直接替换]`）、外观偏好（`[跟随系统]` `[浅色明亮]` `[暗色深邃]`）。
- **反模式禁令 (DON'T)**：**严禁 2 选 1 做下拉**。
- **Checkmark 图标规范细则**：
  - *M3 官方标准*：激活段落应带有 Checkmark 前置图标以满足 WCAG 无障碍识别；
  - *插件紧凑场景特别豁免*：在悬浮球等宽度受限的微型面板中，若选项 $\le 4$ 汉字，允许通过移除 Checkmark 采用纯 `secondaryContainer` 紧凑呈现，但代码中必须明确注释此项为“插件微型化裁剪”，严禁混淆官方标准；
  - *零布局突变（CLS）铁律*：Checkmark 出现/消失**严禁 `display: none <-> inline-block` 直接切换**（选中段文字会在分段间横跳）。Checkmark 必须恒渲染为 flex item（`gap` 恒占位），以 `max-width + opacity + transform` 平滑插值，选中段与非选中段文字位置恒定。

#### C. 操作菜单 (Action Menu) vs 数据选择列表框 (Listbox)
- **严禁混淆 ARIA 语义**：
  - **Menu (`role="menu"` + `role="menuitem"`)**：仅用于**触发动作指令**（如“复制结果”、“朗读发音”、“固定位置”）。动作触发后菜单关闭，**不持久保留选中项**。
  - **Listbox (`role="listbox"` + `role="option"`)**：用于从数据集合中**选定某个值**（如语种选择、LLM 引擎切换）。必须具备 `aria-selected="true/false"`，持久记录当前选中的值。
- **数据多选走 Menu 的 `menuitemcheckbox` 变体**（多源同时查词 / 多 AI 模型对比等高频场景）：
  - **Menu (`role="menu"` + `role="menuitemcheckbox"`)**：多选持久状态以 `aria-checked="true/false"` 表达；
  - 选中指示由**前置 Checkbox 本体**承担（勾选仅染 Checkbox），**严禁整行持久选中染色**；
  - 它与 Listbox 的分工：Listbox 是**单值选定**（`aria-selected` 互斥），`menuitemcheckbox` 是**多值开关**（`aria-checked` 各自独立、可同时多个为 true）。
- **插件级扩展判例（开/关状态图标对）**：`menuitemcheckbox` 承载**单项特性的开/关语义**时（如悬浮球显示开关、划词面板开关行），勾指示允许以**成对状态图标**替代 M3 Checkbox 本体——如 `visibility` / `visibility-off`，lucide/mui 双包成对、随 iconStyle 切换。成对状态图标本质即"勾/空"形态的广义等价，不判违反规范；选中语义仍由 `aria-checked` 承担，持久选中染色禁令与行几何规约不变。此为插件场景裁剪判例，须与"数据多选用 Checkbox 本体"条款区分：**开关一个特性的有无 → 状态图标对；从集合中多选若干项 → Checkbox 本体**。
- **插件级扩展判例（单选状态图标对）**：数据单选伪下拉行（如匹配范围 pattern-option）允许保留**成对 RadioButton 状态图标**（lucide/mui 双包成对、随 iconStyle 切换）作为选中指示，同时选中行以 secondary-container 底色表达。此为对 §5.2 原教旨形态（无图标、纯底色）的插件级偏离，同一载体两种形态不得混用：MUI 基槽真下拉走 §5.2，自绘伪下拉走本判例。
- **染色禁令的适用边界（防扩大化）**：「严禁整行染色」仅约束**持久选中态**（selected / checked 的常驻视觉），**不约束瞬时交互反馈**——hover / active / focusVisible 必须按 §4.2 State Layer（`currentColor` 半透明叠加）保留指针与键盘反馈；以实底 Token 表达悬停、或借染色禁令连带删除悬停反馈，均判违规。

## 四、几何标尺、状态层与抗脆弱度量衡

### 4.1 形状系统标尺 (Shape Scale)
```css
--md-sys-shape-corner-none:        0px;
--md-sys-shape-corner-extra-small: 4px;    /* TextField (Outlined), Menu / Listbox Surface */
--md-sys-shape-corner-small:       8px;    /* Chips (核心规约: 严格为 8px，严禁使用 Pill) */
--md-sys-shape-corner-medium:      12px;   /* Cards, Small Dialogs */
--md-sys-shape-corner-large:       16px;   /* Large Cards, Navigation Drawer */
--md-sys-shape-corner-full:        9999px; /* Buttons, Switch Track, Segmented Controls */
```

### 4.2 状态层（State Layer）解耦法则（彻底根治 48px 触控垫片截断）
- **核心工程陷阱**：若直接在按钮或 Chip 根节点上声明 `position: relative; overflow: hidden;`，会导致通过 `::after` 扩展的 $48\text{px} \times 48\text{px}$ 触控垫片被父容器边缘裁切，触控热区扩展失效。
- **强制解耦架构**：外层节点保持 `overflow: visible`，状态层水波纹下沉为独立的内部绝对定位节点：

```html
<!-- 标准按钮解耦模板 -->
<button class="m3-chip m3-interaction-node">
  <span class="m3-state-layer"></span>
  <span>标签文案</span>
</button>
```

```css
/* 外层容器：保持 overflow: visible，确保 ::after 触控垫片释放 */
.m3-interaction-node {
  position: relative;
  overflow: visible !important;
  cursor: pointer;
  user-select: none;
  outline: none;
}

/* 内部状态层：负责裁剪水波纹与半透明叠色，对事件穿透 */
.m3-state-layer {
  position: absolute;
  inset: 0;
  border-radius: inherit;
  pointer-events: none;
  overflow: hidden;
  z-index: 1;
}

.m3-state-layer::before {
  content: '';
  position: absolute;
  inset: 0;
  background-color: currentColor;
  opacity: 0;
  transition: opacity var(--md-sys-motion-duration-short) var(--md-sys-motion-easing-standard);
}

.m3-interaction-node:hover .m3-state-layer::before { opacity: var(--md-sys-state-hover); }
.m3-interaction-node:focus-visible .m3-state-layer::before { opacity: var(--md-sys-state-focus); }
.m3-interaction-node:active .m3-state-layer::before { opacity: var(--md-sys-state-pressed); }
```
- **与「严禁整行染色」禁令的边界（§3.1.C）**：State Layer 是行级交互的**唯一合法瞬时反馈形态**——hover（0.08）/ focus-visible（0.12）/ active（0.12）的半透明叠加**必须保留**；以实底 Token 表达悬停、或以持久选中染色禁令为由连带删除悬停反馈，均判违规。
- **与焦点环的单形互斥引用（§6.4，v3.3）**：接入 §6.4 环型语义类的节点，focus-visible 档**让位于 outline 环**（同节点染层与环不得双显，见 §6.4「焦点指示单形原则」）；hover / active 两档瞬时反馈不受影响。

### 4.3 触控垫片环境隔离 (`@media pointer`)
- **全覆盖铁律**：凡几何高度 $< 48\text{px}$ 的可交互节点（如 40px 按钮、40px 分段项、32px 紧凑菜单项）一律扩展 48px 触控垫片。依据：WCAG 2.5.8 Target Size (Minimum) AA 级 ≥ 24px、2.5.5 (Enhanced) AAA 级 ≥ 44px——本规范统一按 48px 执行。
- **前提**：4.2 的状态层解耦必须先行（外层 `overflow: visible`），否则垫片被容器边缘裁切失效。唯一例外形态是 `Switch` 等已具备 48px 命中结构的控件可复用既有结构。

```css
@media (pointer: coarse) {
  .m3-switch::after,
  .m3-btn::after,
  .m3-segment-item::after,
  .m3-chip::after {
    content: '';
    position: absolute;
    top: 50%;
    left: 50%;
    transform: translate(-50%, -50%);
    min-width: 48px;
    min-height: 48px;
    width: 100%;
    height: 100%;
    border-radius: inherit;
    pointer-events: auto;
    z-index: 0;
  }
}
```

### 4.4 开关 (Switch) 动力学居中对称算法
Switch 处于 `:active` 按压态时，Thumb（滑块）宽度膨胀至 $28\text{px}$。**必须通过精确位移维持滑块几何中心与轨道端点圆心绝对重合，杜绝偏心抖动**：

```css
.m3-switch {
  position: relative;
  width: 52px;
  height: 32px;
  display: inline-flex;
  align-items: center;
  overflow: visible;
}

/* 1. 未激活态：轨道中心 16px，滑块 16px -> 偏移 8px (16 - 16/2) */
.m3-switch-thumb {
  position: absolute;
  left: 0;
  top: 50%;
  transform: translateY(-50%) translateX(8px);
  width: 16px;
  height: 16px;
  border-radius: var(--md-sys-shape-corner-full);
  background: var(--md-sys-color-outline);

}

/* 2. 激活态：轨道中心 36px，滑块 24px -> 偏移 24px (36 - 24/2) */
.m3-switch input:checked ~ .m3-switch-thumb {
  transform: translateY(-50%) translateX(24px);
  width: 24px;
  height: 24px;
  background: var(--md-sys-color-on-primary);
}

/* 3. 按压态动力学中心保全 (膨胀至 28px) */
/* 未激活按压：中心维持 16px -> 偏移 2px (16 - 28/2) */

  transform: translateY(-50%) translateX(2px);

  transform: translateY(-50%) translateX(22px);

```

### 4.5 菜单与列表框度量衡与视口边缘翻转 (Viewport Collision)
- **宽度钳制区间（Width Clamp，含视口兜底）**：
  ```css
  min-width: 112px;
  max-width: min(280px, calc(100vw - 24px));
  width: max-content;
  ```
  菜单宽度**内容驱动**（`max-content`，跟随最长项），短词保底 $112\text{px}$；超出 $280\text{px}$ 强制 `text-overflow: ellipsis` 截断；上限必须以 `calc(100vw - 24px)` 视口兜底——窄视口（分屏、小窗）下浮层绝不溢出宿主视口，**严禁无视口兜底的定值钳制**。
- **抗脆弱高度与滚动策略**：
  - **短固定菜单（$N \le 5$）**：容器声明 `height: max-content; flex-shrink: 0;`。严禁硬编码绝对高度（避免不同 DPI 缩放下亚像素裁剪底边）。
  - **长数据列表框（$N > 5$）**：设置 `max-height: 280px; overflow-y: auto;`，露出约 5.5 行文字，直观暗示滚动。
  - **短菜单高度预算锁**：短固定菜单的任何高度上限（如需设 `max-height` 兜底）必须 ≥ 行数 × 行高 $48\text{px}$ ＋ 行间距 ＋ 容器上下 padding ＋ 边框；**滚动条把任何一行顶出可视区即判为预算失准**。行高统一为 $48\text{px}$ 后，历史行高时代的容器高度预算必须同步重估。
  - 二类判据是「选项是否应同屏完整可见」，不是行数绝对值：短菜单滚动条是缺陷，长列表滚动是设计意图。
- **视口碰撞翻转指南**：
  浮层在宿主页面底部展开时，必须检测视口下边界空间。若 `bottom + menuHeight > window.innerHeight`，应将浮层由默认的“向下展开（Bottom）”翻转为“向上展开（Top）”。

### 4.6 下拉入口（触发框）本体度量衡与语义配对 (Trigger Entry Audit)
- **入口本体纳入审计与锁**：下拉入口（触发框）本体同样受审计与夹具锁约束——真下拉（MUI Select / combobox）与伪下拉（自绘菜单触发钮）一律适用；下游菜单内部合规**不得替代或豁免入口本体检查**。
- **几何与字体逐项入锁**：入口高度、padding、圆角、字号、字重、行高、文本溢出（`ellipsis`）逐项须有夹具与测试钉住，缺锁即红。
- **选型铁律同树约束**：入口控件类型同样受 §3 排他性决策树约束（二元布尔误用下拉、$2 \le N \le 5$ 短文案误用下拉等即红），不得因下游菜单合规而豁免。
- **语义配对登记**：入口必须声明 `aria-haspopup`、`aria-expanded` 与 `aria-controls`（v3.3 键集，与下方「入口 aria 声明与翻转义务」一致），并登记下游菜单语义类型（动作菜单 / 数据单选 / 数据多选），决定下游按 §3.1.C 哪一分支审计——入口与下游类型不匹配即红。
- **状态与回退**：hover / active / focusVisible 按 §4.2 State Layer 保留瞬时反馈；焦点环遵守 §6.4 配对法则；`Escape` 收起浮层后焦点必须回退至入口本体（§6.3 opener 接线义务）。
- **已知载体（非穷尽，以 grep 盘点为准）**：悬浮球菜单、划词翻译菜单、FileTranslate 域 SettingsSelect / ScenePromptSelect。
- **仓库基准载体登记（v3.3）**：下列载体为本节条文的审计锚，新增同类入口必须对号入座（清单以 grep 盘点为准）：
  - `SettingsSelect`（`src/views/Options/SettingsCard.js`）——真下拉底座（MUI TextField select），Options 域经 `DropdownRoot`（`src/views/Options/DropdownRoot.js`，Popper 浮层容器）承载下游列表；
  - `ContentFab` 触发钮（`src/views/Action/ContentFab.js`）——Popper＋MenuList 自组装浮层，触发钮已声明 `aria-expanded` / `aria-haspopup` / `aria-controls`（本节基准实现）；
  - `TranslationPanel/Header` 触发钮（`src/components/TranslationPanel/Header.js`）——自绘 `role="menu"` 浮层；
  - `subtitle/Menus.js`——纯自绘 div 菜单（零 MUI、零焦点环现状），入口与浮层须按本节与 §6 全量自证；
  - Popup 伪下拉（`src/views/Popup/PopupTextPanel.js`＋`CompactLanguageSelect.js`）——自绘 `role="combobox"` 触发框＋`role="listbox"` 浮层。
- **入口 aria 声明与翻转义务（v3.3）**：
  - **声明义务**：入口本体必须声明 `aria-haspopup`（取值与下游语义配对：动作菜单→`menu`、数据单选→`listbox`、对话框→`dialog`）、`aria-expanded`（实时开合态）与 `aria-controls`（指向浮层 id）；下游语义类型并入上方「语义配对登记」按 §3.1.C 分支登记。
  - **翻转义务**：开合状态变更必须在同一事件流内同步翻转 `aria-expanded`（JS toggle 流程内联完成；只改视觉不改状态＝违规）。
  - **回退义务（互引，不重述）**：`Escape` 收起浮层后焦点回退至入口本体——按上方「状态与回退」与 §6.3 opener 接线义务执行，本节不另立措辞（防两处漂移）。

### 4.7 窄屏 / 移动端行为基线 (Responsive Behavior Baseline)

- **改向必声明交叉轴**：flex 网格在窄屏断点将主轴由 `row` 改 `column` 时，**必须同步重设交叉轴对齐**（`align-items`）。`align-items: flex-start` 在列向会收缩项目水平宽度致整列左堆；需满宽者显式 `align-items: stretch`。改向只动 `flex-direction` 而漏声明交叉轴＝缺陷。
- **卡片宽度恒定原则**：展开/折叠**只允许改变卡片纵向尺寸（行高），禁止改变横向宽度**。凡宽度依赖内容固有宽（列容器 `flex:1 1 0` 在列向只管主轴）即违规；窄屏应使卡片成为满宽网格直接项目（如列容器 `display: contents` 升格），杜绝「展开拉宽本卡并连带同容器兄弟卡共振变宽」。
- **折叠后 DOM/Tab/阅读序＝逻辑序（无障碍强制）**：多列/瀑布流分布（如第 i 项入第 i%N 列）折叠为单列后，DOM 文档序不再等于数据序（列优先展平 → 0,2,1,3）。**必须让视觉序＝DOM 文档序＝Tab 序＝读屏序＝数据序**——通过在文档序层面重排（如对半切分 `[0,mid)`/`[mid,len)`）达成。**严禁用 CSS `order` 修阅读序**：`order` 仅改 flex 视觉序、不动 DOM 树序，会造出"视觉对、焦点/读屏序错"的 WCAG 2.4.3 缺陷，且 jsdom 只读 `style.order` 属性在场、测不出。`order` 只可用于无可聚焦后代的纯装饰重排，永不用于修复内容阅读顺序。
- **含操作簇的设置行水平豁免（opt-in 机制）**：全局窄屏把设置行改竖排（`flex-direction: column`）时，须保持水平（label 居左、控制簇居右）的操作簇行**必须经行级显式豁免类逐行打标**（如 `.kt-settings-row--inline-control`）；未打标行随全局竖排、零变化。含操作簇且意图水平却未登记豁免＝缺陷。注：本条以 **opt-in** 兑现（默认仍竖排、水平靠打标）；「全局默认水平、竖排反向豁免」为更彻底终态，涉全库其余行窄屏版式回归面，须人类单独裁决扩面，现行基线以打标机制为准。
- **触控最小尺寸**：窄屏触控目标引用 §4.3（`@media (pointer: coarse)` 48px 垫片），操作簇成员不得因窄屏收缩到 < 最小可触面积。
- **禁 JS 布局分支**：响应式一律 CSS 容器查询 / `@supports`，禁 `matchMedia` 判定布局形态。

### 5.3 文本输入框 (Outlined TextField) - 消除背景白块穿帮
- **缺陷分析**：标签上浮时若硬编码 `background: var(--md-sys-color-surface)`，嵌套在深色卡片或 Container 容器中会产生明显的白色方块穿帮破损。
- **容器级联方案**：父容器暴露 `--m3-current-container-bg`，Label 自动同步父容器背景：

```css
.card-panel {
  --m3-current-container-bg: var(--md-sys-color-surface);
  background-color: var(--m3-current-container-bg);
}

.m3-text-field-label {
  position: absolute;
  left: 12px;
  top: 50%;
  transform: translateY(-50%);
  font-size: 15px;
  color: var(--md-sys-color-on-surface-variant);
  background-color: var(--m3-current-container-bg, var(--md-sys-color-surface));
  padding: 0 4px;
  pointer-events: none;
  transition: top 0.15s, font-size 0.15s, color 0.15s;
}

/* 1. 位置上浮：只要获得焦点或有内容填入，统一升至顶部 */
.m3-text-field-input:focus ~ .m3-text-field-label,
.m3-text-field-input:not(:placeholder-shown) ~ .m3-text-field-label {
  top: 0;
  font-size: 12px;
}

/* 2. 颜色解耦：仅在获得焦点(:focus)时染 Primary 色，失焦退回灰调 */
.m3-text-field-input:focus ~ .m3-text-field-label {
  color: var(--md-sys-color-primary);
}
.m3-text-field-input:focus {
  border-color: var(--md-sys-color-primary);
  box-shadow: 0 0 0 1px var(--md-sys-color-primary); /* 防抖动替代 physical 2px border */
}
```
- **高保真场景升级路径**：`--m3-current-container-bg` 背景遮罩在渐变、`backdrop-filter` 磨砂卡片或未显式暴露该变量的深层嵌套容器下会露出纯色底块。此类场景应改用纯 CSS 的 `<fieldset><legend>` 裁切法（MUI Outlined Input 同源技法）实现物理缺口，彻底摆脱对背景色变量的依赖；轻量场景保留上述变量级联方案即可。

### 5.5 胶囊按钮组（假分体 / Split Button Capsule Group）

- **定性**：Material 3 **没有一等分体按钮（split button）组件**，官方对真分体按钮（单一控件带拆分主/箭头条）因触控误触顾虑不推荐，其推荐替代即「两个独立按钮成组 / button group」。本组件是该替代形态的**胶囊收紧版**——两枚完整按钮以 2px 缝拼合、外侧全圆内侧 4px，视觉上成一枚胶囊，语义上是两个恒定义成员。**属项目扩展组件，非引用 M3 官方；不得自封「M3 标准」。**
- **动机**：当「打开/收起某区域」与「在该区域新建」两动作原分散于行右侧开关钮与区域角落孤悬新建钮时，收编为一组消除孤悬按钮、降低页面破坏；九类语义（功能×通道）经**结构消解**——每成员恒定义，无需奇偶/双击/右击/长按/悬停门控等技巧填满。
- **结构铁律**：
  - 组容器 `role="group"` + `aria-label`（标组语义）；成员为完整 MUI `Button`（非自绘）。
  - **每成员语义恒定**：leading 恒＝其单一动作、trailing 恒＝其单一动作；禁止任一成员因另一成员状态、点击次数、点击节奏或输入通道（鼠标/触屏/键盘）改变语义。违反＝读屏/可达性自相矛盾。
  - leading 携 `aria-haspopup`（弹层类）或相应语义；trailing 携 `aria-expanded` + `aria-controls`（指向受控区域 id）。
  - 几何：外 `border-radius` 全圆（9999px）、内侧接缝 4px（extra-small token）、成员间 `gap: 2px`；成员保持 small 尺寸，由组规则 `min-height: 40px` 统一抬至 medium 触控高度（40px，不改写成员主题几何）。
  - 状态层（hover/active/focusVisible）与焦点环全部走成员 MUI `Button` 主题既有形态，**组壳不造环、不叠 State Layer**（§4.2/§6.4）；`forced-colors` 交成员兜底。

## 六、无障碍 (WAI-ARIA) 与键盘导航联动算法

### 6.1 Roving Tabindex 规约
在 `radiogroup`（分段控制器）、`listbox`（选项列表）与 `menu`（动作/多选菜单）内：
- **容器严禁持有焦点**（不得声明 `tabindex="0"`）——容器焦点 + 子项 `.focus()` 的混合模式会造成两段式焦点停滞与读屏播报紊乱（W3C APG 两种模式严禁混用）；
- 仅处于选中激活态的一项声明 `tabindex="0"`（无固有选中态的 Menu 取第一项作 Tab 入口）；
- 其余未选中的各项统一声明 `tabindex="-1"`；
- 用户按 `Tab` 键时，焦点仅穿透当前激活项并直接离开组件，内部项切换强制通过方向键进行。

### 6.2 垂直与水平导航算法（防越界负模修正）
处理初次聚焦到外壳容器（此时 `currentIndex = -1`）时的键盘计算，**杜绝初次按 `ArrowUp` 命中倒数第 2 项的数学 Bug**：

```javascript
/**
 * 健壮的垂直键盘导航算法
 * @param {KeyboardEvent} e
 * @param {HTMLElement[]} items 可聚焦元素列表
 * @param {number} currentIndex 当前活动项索引，-1 表示未激活任何子项
 */
function getNextNavIndex(e, items, currentIndex) {
  if (items.length === 0) return -1;

  if (e.key === 'ArrowDown' || e.key === 'ArrowRight') {
    return currentIndex === -1 ? 0 : (currentIndex + 1) % items.length;
  }
  if (e.key === 'ArrowUp' || e.key === 'ArrowLeft') {
    // 算法修复：currentIndex 为 -1 时按向上键正确命中末尾项 (length - 1)
    return currentIndex <= 0 ? items.length - 1 : currentIndex - 1;
  }
  if (e.key === 'Home') return 0;
  if (e.key === 'End') return items.length - 1;

  return -1;
}
```

### 6.3 焦点回退机制 (Focus Restoration)
- 用户在菜单或气泡面板中按下 `Escape` 键收起浮层时，**严禁简单调用 `menu.blur()`**（焦点会掉入 `document.body`，纯键盘用户丢失浏览位置）；
- 脚本必须显式保存打开该浮层的**触发按钮（Trigger Element）引用**，并在浮层收起后调用 `triggerEl.focus()`，确保盲人读屏或纯键盘用户焦点流不中断；
- **opener 接线义务**：触发源引用必须在浮层打开时由打开方挂载（如 `surface._m3TriggerElement = triggerBtn`）；`Escape` 处理器只消费该引用——引用缺失时**宁可保留焦点原地，也绝不盲目 `blur()`**。

### 6.4 无障碍焦点环配对法则 (Focus Ring Pairing Law)
> 本节是**独立纳入审计**的验收域：焦点环配对本身入审入锁；§6.2/§6.3 的键盘导航**算法细节**维持既有排除口径，两者不互含、不互豁免。
- **无语义必无环**：未接入键盘导航与 ARIA 语义（无 roving tabindex、无 menu / listbox / option / combobox 等角色、无键盘事件接线）的组件，**严禁渲染任何形态焦点环**（`:focus-visible` 样式、`.Mui-focusVisible` 覆盖、outline / box-shadow 环均在内）——“根本没用无障碍却主动开焦点环”直接判违规。
- **有语义必有环**：已接入无障碍语义的组件**必须配对焦点环**，环必须挂键盘语境伪类 `:focus-visible`（**严禁**挂输入方式无关的 `.Mui-focusVisible` 类——鼠标链路会误显环）；`forced-colors` 模式必须提供 outline 兜底形态。
- **静默作用域一致**：指针静默机制（focusModality 标记＋抑制 CSS）注入域必须与焦点环样式作用域一致——自建 ThemeProvider 的域若画环必须同步接入静默机制，任一单侧存在判配对断裂。
- **夹具双向钉死**：有语义处断言环形态（`:focus-visible` 键＋`forced-colors` 兜底），无语义处负向锁断言环样式键不存在；本项夹具与测试此前完全缺失（焦点环缺陷靠用户报告才发现、多轮才收敛），列为最高优先盲区，**缺失即红**。

**实施细则（v3.3 增补）**：

- **焦点指示单形原则**：同一交互节点在同一焦点态下，State Layer 焦点染层（focus 档）与 outline 焦点环**不得双显**——双显即双份焦点指示，判实现冲突。节点先按上方「无语义必无环／有语义必有环」定环之有无，再按本原则定形态，三分如下：
  - **环型语义类**：接入 roving tabindex 与 `menu`/`menuitem`、`listbox`/`option`、`combobox`、`radiogroup`（segmented）、下拉入口/触发钮、FAB 等 ARIA 语义与键盘接线的节点——`:focus-visible` outline 环为**唯一**键盘焦点指示，State Layer focus 档对该节点**互斥禁用**（hover / active 两档瞬时反馈不受影响，§3.1.C 染色禁令边界仍适用）；
  - **染层型（无环语义类）**：具备原生焦点可达性但按本规范裁定不画环的节点（如纯文本链、整卡可点击区、仅带 `aria-pressed` 未接入键盘导航的 Chip）——State Layer focus 档 0.12 为其唯一焦点指示，**严禁另画环**（唯一例外：forced-colors 模式下的 outline 兜底，见下方模板——彼时染层失效，outline 是唯一焦点指示，不构成单形违反）；
  - **无语义类**：未接入键盘导航与 ARIA 语义且不具焦点可达性的节点——环与 focus 档染层**双双不存在**。
  - 环型类节点若同时渲染 focus 染层、或染层型节点另画环，均判**单形违反**。本原则是对 §3.1.C「State Layer 瞬时反馈必须保留」的范围细化：仅 focus 档在环型类节点上让位于环，hover/active 档零变化。
- **forced-colors 兜底实现模板**：强制色彩模式下系统强制前景/背景，半透明染层与 box-shadow 环全部失效，环型语义类**逐类**提供 outline 兜底；**染层型节点同模板提供同形态兜底**（作用于该节点自身的 `:focus-visible`，属「严禁另画环」在本节的显式例外）：

```css
/* 兜底块必须置于同选择器 :focus-visible 规则之后（顺序闸契约，对齐 src/styles/m3.test.js 既有规则顺序断言） */
@media (forced-colors: active) {
  .<语义焦点选择器>:focus-visible {
    outline: 2px solid CanvasText;
    outline-offset: 2px;
  }
}
```

  `outline-color` 使用系统关键字 `CanvasText`（与 Shadow DOM 禁硬编码 Hex 同源口径）。**染层型必须兜底、无语义类无需兜底**：染层型节点依赖的半透明染层在 forced-colors 下被固化为不透明系统色、不再是可分辨的焦点指示，且宿主页面的全局 outline 清除（`*:focus { outline: none }` 类）可能吞掉 UA 默认焦点形态——显式声明 2px CanvasText 是唯一可靠兜底，作为「严禁另画环」的显式例外登记（彼时染层已失效，outline 不构成双显，不违反单形原则）；无语义类不具焦点可达性，无需兜底。
- **focusModality 同域接入细则**：指针静默机制＝**模态标记＋抑制 CSS**，两者必须与焦点环样式**同注入域**（同一容器级联域 / 同一 Shadow Root）：
  - 监听层：`pointerdown`（含触摸）置**指针模态**标记，`keydown` 置**键盘模态**标记（二态互斥切换）；
  - 抑制层：指针模态活跃期间抑制 `:focus-visible` 环形态（染层型同步抑制 focus 档），键盘模态恢复；
  - 配对义务：自建主题域（自建 ThemeProvider / Shadow Root 沙箱）若画环必须同步接入静默机制，缺侧即判「静默作用域一致」配对断裂；
  - 仓库实现基准：`src/hooks/focusModality.js`（模态二态 hook，含配套行为测试；现位于仓库图标基线分支，合入主线前以本节机制语义为准，**不绑定分支**——锁契约见附录 A）。
- **语义分流环细则（正面登记）**：环型语义类逐类登记环形态，实现与夹具按此对号：

| 语义类 | ARIA 接线 | 环形态 |
|---|---|---|
| menu / menuitem | roving tabindex＋方向键 | 成员 `:focus-visible` outline 2px（offset 2px），容器零焦点（§6.1） |
| listbox / option | roving tabindex＋`aria-selected` | 同上；选中底色（secondary-container）与环并存——环只表焦点、底色只表选中 |
| combobox 触发框 | `aria-haspopup`/`aria-expanded` | 触发框 outline 2px；展开后焦点入列表按 listbox 形态 |
| segmented（radiogroup） | roving radio | 激活/聚焦段 outline 2px；Checkmark 表选中，不与环混义 |
| 下拉入口/触发钮 | `aria-haspopup`/`aria-expanded`/`aria-controls` | outline 2px＋forced-colors 兜底 |
| FAB | `aria-expanded`/`aria-haspopup`/`aria-controls` | 内嵌 3px 环（对齐仓库既有实现形态）或 outline 2px，二选一登记后恒定；forced-colors 概用 outline 兜底 |

- **负向锁判定口径**：无语义类节点样式文本（编译产物 / emotion head style / `M3_GLOBAL_CSS`）中不得存在 `:focus-visible` 环样式键（outline / box-shadow 环）与 `.Mui-focusVisible` 覆盖键，亦不得存在作用于该节点的 focus 档染色规则；染层型节点不得存在环样式键（focus 档染层除外）。断言口径统一走附录 A 夹具映射。

### 6.5 Shadow 拓扑下的 MUI 弹层焦点契约（三键同给＋交接单所有权）
> 本节是**独立纳入审计**的验收域：弹层焦点交接与 enforceFocus 条件化入审入锁；§6.1/§6.3/§6.4 既有法则维持互引不重述。

- **isShadowMenu 判据**：菜单是否需要禁用焦点陷阱，判据取**菜单最终挂载容器**解析后的根节点 host 存在性（`container().getRootNode().host != null`），**不取锚点根**——容器解析回退（`closest(".kt-m3-root") || body`）可能把影子内锚点的菜单挂回 document，此时焦点约束必须保持；跨 realm（另一 window 的 ShadowRoot）以 host 存在性判定，`instanceof ShadowRoot` 会漏判。
- **三键同给（无条件）＋交接单所有权**：MUI Menu 弹层必须同时声明 `autoFocus={false}`＋`disableAutoFocus`＋`disableAutoFocusItem`，缺一不可——分别封死 MenuList 容器聚焦腿、Modal 自拓焦腿、选中项聚焦腿；焦点交接的**唯一所有权归 scriptFocus**（打开时由弹层方主动交付）。只关其中一腿时 MUI 剩余路径仍会在**指针开菜单**时命中 `:focus-visible`，长出用户从未请求的焦点框。
- **disableEnforceFocus 条件化**：`disableEnforceFocus = isShadowMenu`。机制：面板整体在 shadow DOM 内时，文档级 `focusin` 对树内目标的 `event.target` 被重定向为 shadow host，MUI FocusTrap 以树级 `contains` 判定焦点归属，恒判「焦点逃逸」并把焦点拉回 Paper，吞掉脚本交付给菜单项的焦点；非 shadow 拓扑不得禁用（否则 Tab 焦点可逃逸出弹层）。
- **scriptFocus 单一入口**：弹层内脚本化移动焦点零裸 `.focus()`——shadow 内 `document.activeElement` 只到宿主，落点判定与标记清理必须下钻（`getRootNode()` / `composedPath()`）；静默标记必须带 **landed 校验**（focus 未落地不挂标记），防止 focusout 永不发生导致永久静默。
- **初始焦点优先级＋容器兜底禁令**：打开弹层时交付顺序为 `option[aria-selected="true"]` → `Mui-selected` → `menuitem` 族首个可用项；**listbox 载体扩展（v3.5）**：menuitem 族兜底腿对 listbox 载体并含未选中可用 `role="option"`（排除 `.Mui-disabled` 与 `aria-disabled="true"`）——数据单选合法存在"打开时无选中项"状态，§6.1 roving tabindex 下焦点不落 option 则方向键失联；menu 载体内无 option 节点，该腿惰性。**找不到可聚焦项就不聚焦（宁缺勿错）**，严禁回退聚焦 `[role="menu"]` / `ul` / `[role="listbox"]` 容器本体——容器抢焦既违 §6.1 零焦点，又令不命中项选择器的网格形态方向键失效。
- **抑制规则单一定义、按注入域分发**：`FOCUS_SILENT_CSS` 为**唯一常量**（`src/styles/m3.js` 具名导出）；`M3_GLOBAL_CSS` 注入域经其插值并入；M3Theme/State 安装路径不覆盖的挂载域（实证：字幕菜单挂在宿主 YouTube 文档 light DOM `#kiss-subtitle-menus`，`M3_GLOBAL_CSS` 在该域不可达）必须**显式注入同一常量**；任何域手写复刻副本即违例（值/角色/形态漂移）。
- **关闭回退落点（实证口径）**：显式 opener 回退必须保留且经 `scriptFocus`（随模态决定指针静默/键盘出环，满足 §6.4 配对法则与 §6.3 opener 义务）；MUI 默认 restore 允许并行存在。实测复合落点正确（关闭后焦点回入口）；机制归因未定（MUI `nodeToRestore` 取 `document.activeElement`＝shadow 宿主、不下钻），「删除手动回退只信 MUI restore」与「禁双轨」均不作无证据断言（遗留取证项）。
- **滚动同步义务（v3.5 增补 2，实证缺陷收编）**：`scriptFocus` 的 `preventScroll: true`（脚本聚焦不拖宿主页面）把滚动责任**转移给弹层方**——初始焦点交付与方向键导航聚焦后，**必须把焦点项滚入滚动容器的可视区**，否则「焦点在视区外项、滚动条停滞」即无障碍焦点与滚动条脱节（重开时"焦点在末项、滚动条仍在顶部"）。实现口径（`PopupMenu.js` focusFirstItem 实证）：手算视口矩形增量、**只调容器自身 `scrollTop`**，严禁使用会波及宿主页面滚动链的全局 `scrollIntoView`。对非滚动容器为无操作。
- **作用域登记义务**：模态监听与抑制规则的挂载点（`.kt-m3-root` / `.kt-focus-silent-scope` / `.kt-subtitle-menus` 及后续新载体）随新挂载域登记进判据清单；漏登记判未通过（该域内静默标记恒缺失或恒越界）。
- **测试锁清单**：容器不抢焦（`ul.focus` spy 恒 0）／三键 prop 逐键锁／isShadowMenu 判据锁（shadow 容器→true、document 容器→false）／模态机锁（pointerdown 置假、键盘导航键置真、per-document 幂等）／单源锁（`FOCUS_SILENT_CSS` 具名导出＋`M3_GLOBAL_CSS` 插值并入＋顺序闸）／滚动同步锁（脚本聚焦视区外项后容器 `scrollTop` 增量≠0 且 `window.scrollY` 恒 0——只滚容器不滚宿主页面）。
